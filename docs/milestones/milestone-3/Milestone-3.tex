\section{Executive Summary}
This submission covers Sprint 1 and Sprint 2 user story implementation focused on backend API development and validation. The backend APIs are implemented in FastAPI, documented in Swagger compatible YAML, and validated with integration tests using pytest. The frontend now includes an API Docs page at \apipath{/api-docs} that embeds Swagger UI from the backend.

\section{API Exposure Policy}
\subsection{Should all APIs be public?}
No. All APIs should not be publicly writable or publicly readable by default.

The correct approach for this project is:
\begin{itemize}[leftmargin=1.2cm]
  \item Keep authentication endpoints public for onboarding and login.
  \item Keep read only informational endpoints public only when needed.
  \item Keep all business sensitive or user specific endpoints protected with JWT based authorization and role checks.
\end{itemize}

This policy is already implemented in backend route guards, and is now explicitly documented through the API Docs page and OpenAPI specification.

\subsection{Public vs protected examples}
\begin{itemize}[leftmargin=1.2cm]
  \item Public examples: \apipath{/api/auth/register}, \apipath{/api/auth/login}, \apipath{/api/doctors}
  \item Protected examples: \apipath{/api/orders}, \apipath{/api/cart}, \apipath{/api/staff}, \apipath{/api/customers}, \apipath{/api/inventory}
\end{itemize}
